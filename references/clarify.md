# clarify —— 画图前先把「需求」问清楚(data.ir 的上游)

> **链路**:`clarify(产出 brief)→ data.ir(brief + input + context → 结构 + scope)→ dispatch → encoding → render → lint`。
> **何时用**:自由信息可视化(架构/解释/信息图/关系)。原型/固定 mermaid 仍需基本澄清,但不进 data.ir。
> **目标**:用**最少的打扰**,定下决定下游一切的几个判据——别问 20 个问题。
> clarify 定「为谁、答什么问题、什么算重要」;data.ir 拿这判据去切真实信息。

## 产出:brief(喂给 data.ir)

```jsonc
{
  "audience":  "谁看 + 专业度",            // → 定颗粒度(高管粗 / 工程师细)
  "purpose":   "看完做什么决策/动作",      // Munzner action+target → 定边界 & 谁是 hero
  "question":  "这张图回答的唯一问题",      // → data.ir.message 的种子(BLUF)
  "scope_hints": { "must_include":[...], "out":[...] },  // 用户明示的范围
  "constraints": "尺寸/介质/格式/已有 context 与资产"
}
```

## 方法锚(科学依据)

- **Munzner what/why/who**:别只问 WHAT(数据),先问 **WHY(任务/支持什么决策)+ WHO(受众)**。任务抽象才是核心。
- **GQM**:Goal → Question(唯一问题)→ Info(什么信息能回答)。
- **BLUF / 单问题框定**:逼出一个 governing question,早定。
- 即 SKILL.md「design pre-questions(受众+目的+一句话 takeaway)」的系统化。

## 流程

1. **先读 context**:代码 / 文档 / 截图 / 已有架构图。**能查到的绝不问**(事实先于假设)。
2. **找决策相关的未知**:受众、目的、那个唯一问题、范围边界。只盯**改变结果**的未知,其余不问。
3. **逐个未知决定问不问**:
   - 能从 context 自信推断 → **推断 + 声明假设**(让人可纠正),不打断。
   - 真分叉且高影响 → **才问**:用 AskUserQuestion,2–4 选项,**带推荐默认**(沉默=接受)。
4. **大堆 / 异质 context → 强制范围澄清**:输入大或杂时(可计算:体积、子团数、类型数),关键一问自动变成**范围题**——「这张图最想说的**一件事**是什么?给谁看?」。这正是给那堆料定界、并触发 data.ir 的 `scope`(边界/颗粒度/拆几张)。
5. **输出 brief**,交给 data.ir。

## 三分(谁来做)

- **可计算**:检出「该不该强制范围澄清」(输入体积 / 关系子团数 / dataset_type 种类数);从结构化 context 预填部分 brief(受众有时能从 repo/文档推)。
- **概率大模型**:生成**好的澄清问题**、推断受众/目的、把模糊需求归纳成一个 question。
- **人**:回答澄清、拍板受众与目的、给范围 hint。

## 什么算「好 clarify」

- 收尾时有:**一个可回答的 question + 已知受众 + 已知目的**;
- **只问了少数几个、且都决策相关**的问题(没有审问);
- 对推断的项**声明了假设**(用户能纠);
- 输入大时**早早抛了范围题**,而不是闷头开画。

**边界**:问得准不准、归纳得对不对仍是语义(靠模型 + 人);本方法固定的是**流程与判据**,不替你判断内容。
