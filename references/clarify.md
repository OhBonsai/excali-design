# 澄清:需求 → brief(你在画图前先做什么)

用户给了一个画图需求。**在抽 data.ir、动笔之前**,你先把需求问清楚,产出一个 `<name>.brief.json` 喂给 data.ir。

你的目标:用**最少的打扰**,定下决定下游一切的几个判据——**别问 20 个问题**。
你这一步只定「为谁、答什么问题、什么算重要」;data.ir 才拿这判据去切真实信息。

**何时做**:自由信息可视化(架构/解释/信息图/关系)。原型/固定 mermaid 仍需基本澄清,但不进 data.ir。
**强制**:必须产出 `<name>.brief.json`(模板 `examples/data-ir/_TEMPLATE.brief.json`),它和 `<name>.data-ir.json` 是画图前的硬门。

## 工作流

1. **先读 context**:代码 / 文档 / 截图 / 已有架构图。**能查到的绝不问**——事实先于假设。
2. **找决策相关的未知**:受众、目的、那个唯一问题、范围边界。只盯**会改变结果**的未知,其余别问。
3. **逐个未知,决定问还是推**:
   - 能从 context 自信推断 → **直接推断 + 声明假设**(让用户能纠正),不打断;
   - 真分叉且高影响 → **才问**:用 AskUserQuestion,2–4 个选项,**带推荐默认**(沉默=接受)。
4. **输入大/杂 → 抛范围题**:输入体量大或异质时(可计算:体积、关系子团数、dataset_type 种类数),
   关键一问自动变成**范围题**——「这张图最想说的**一件事**是什么?给谁看?」。这给那堆料定界,并触发 data.ir 的 `scope`(边界/颗粒度/拆几张)。
5. **写 brief**,交给 data.ir。

## 产出:brief.json

```jsonc
{
  "audience":  "谁看 + 专业度",            // → 定颗粒度(高管粗 / 工程师细)
  "purpose":   "看完做什么决策/动作",      // → 定边界 & 谁是 hero
  "question":  "这张图回答的唯一问题",      // → data.ir.message 的种子(一句话结论先行)
  "scope_hints": { "must_include":[...], "out":[...] },  // 用户明示的范围
  "constraints": "尺寸/介质/格式/已有 context 与资产"
}
```

## 什么算「问得好」

- 收尾时手上有:**一个可回答的 question + 已知受众 + 已知目的**;
- **只问了少数几个、且都决策相关**的问题(没有审问);
- 对推断的项**声明了假设**(用户能纠);
- 输入大时**早早抛了范围题**,而不是闷头开画。

## 分工

- **程序能做**:检出"该不该强制范围澄清"(输入体积 / 关系子团数 / dataset_type 种类数);从结构化 context 预填部分字段(受众有时能从 repo/文档推)。
- **你(LLM)做**:生成**好的澄清问题**、推断受众/目的、把模糊需求归纳成一个 question。
- **人做**:回答澄清、拍板受众与目的、给范围 hint。

## 边界

问得准不准、归纳得对不对仍是语义(靠你 + 人);本流程固定的是**步骤与判据**,不替你判断内容。
方法依据(Munzner what/why/who、GQM、BLUF)见 `iterate/clarify-design.md`(不必读也能干活)。
